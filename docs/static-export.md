# 靜態部署與附近優先載入

本次方案依使用者確認：網頁純靜態匯出，瀏覽器非同步取得即時站點；附近資料優先，完整三市資料背景補齊。

## 執行與部署

- `npm run dev`：先產生站點靜態索引，再啟動本機開發環境。
- `npm run build`：下載官方站名／地址／座標清單，產生小區塊索引，再輸出 `out/`。建置不抓取或固定即時車位。
- `npm start`：在 3210 埠提供 `out/` 靜態檔案，沒有 Next.js 執行期或 API。
- 正式部署只需上傳完整 `out/` 至 HTTPS 靜態主機。`npm start` 是本機預覽工具，並非部署的必要服務。
- 站點增設、撤站、名稱／地址變更需重新建置。車輛與車位數由瀏覽器直接取得，不需重新建置。

## 載入與更新

1. 分享網址的地圖位置優先，否則立即採用上次位置或板橋。裝置定位同時進行，不阻擋地圖。
2. 先要求低精度或裝置快取位置（最長等待 2.5 秒），成功就顯示位置，再背景要求高精度。使用者已拖動地圖或選站後，自動定位不再拉回地圖。
3. 先取所在區塊的靜態站名／座標，與官方 `POST /tw2/parkingInfo` 的附近即時狀態合併顯示。
4. 背景下載完整三市靜態索引，以最多三個並行查詢逐批補齊即時資料。只用資料更新列表和圖標，不改變地圖中心。
5. 目前視野每分鐘更新，完整背景資料最多每五分鐘更新一次；移動到遠處會優先查詢新的附近站點。查詢半徑的官方 10km 上限僅作用於單次請求，不限制可瀏覽地區。

保留 `tp-`、`ntpc-`、`kcg-` 站點 ID，因此收藏、取樣與分享連結不需遷移。API 失敗保留本次開頁已取得資料；背景或離線狀態不保證維持更新頻率。

## 瀏覽器服務與限制

站點即時來源為 `https://apis.youbike.com.tw/tw2/parkingInfo`，使用匿名 CORS 請求。資料來源與網路狀況會影響可用性。瀏覽器分別查詢，不再有跨使用者共用的伺服器快取。

裝置定位失敗時先沿用上次位置；沒有上次位置才向 `https://ipapi.co/json/` 查詢網路區域，將使用者 IP 暴露給該服務。該服務失敗則留在板橋。IP 定位不是裝置精確定位。

舊地標 API 已移為 `lib/landmarks.mjs` 的 `fetchLandmarks(params)`，可供瀏覽器直接查詢 Overpass；目前頁面並未啟用地標功能。

HTTP/3 由正式主機或 CDN 設定，保留 HTTP/2、HTTP/1.1 回退。本次未修改外部主機設定；HTTP/3 不會加速裝置定位或決定第三方服務的通訊協定。

## 驗證

`npm test` 檢查 ID 相容、附近優先、背景合併、失敗保留資料與定位呼叫順序。另需在 `npm start` 提供的靜態頁面檢查實際 CORS、定位、分享參數、篩選、收藏與地圖互動。
